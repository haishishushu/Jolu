# 统一网关：来源与最近会话开发说明

> 日期：2026-11-06。状态：第 1–5 步已实现，真实桌面验收见 `docs/verification/2026-11-06-unified-gateway-desktop.md`；补充决定见 §8.1。
> 唯一视觉依据：`docs/ui/Jolu.pen`。导出截图只用于辅助查看，不能替代画板。

## 1. 目标与已确认范围

将主窗口「模型入口」统一命名为「统一网关」，把原来的「模型来源 → 模型池 → Agent」展示区域替换为「模型来源 → 最近会话」。来源直接以发光曲线关联会话，正在运行 AI 的会话优先展示，每条会话右侧显示累计 Token。

同时完善单行连接信息栏和路由流水分页。保留现有网关的服务、接线、认证、模型目录、管理入口及安全操作。展示结构变化不改变实际选路逻辑。

已确认事项：

- 本轮主稿为浅色，保留 Jolu 现有主窗口外壳。
- 中间不再展示模型池节点，右侧不再以 Agent 分组卡作为主图终点。
- 模型来源与最近会话位于同一滚动区域，共用纵向滚动条。
- 最近会话先显示多条，更多内容通过底部下拉入口展开、收起。
- AI 运行中的会话排在最前，运行关联以亮线与流光强调。
- 每条会话右侧展示累计 Token。
- Base URL 可以复制；API Key 可以复制、刷新；连接信息放在一行。
- 路由流水默认每页 10 条，复用项目现有分页样式。
- 路由流水不增加来源或会话分类；鼠鼠已明确这里需要的是「分页」。

本轮不包含：安装包构建、Git 提交或推送、供应商适配扩展、多次故障转移记录、新增路由策略，以及浮动灵动岛的外观改造。

### 3.1 单行连接信息

- `PA0Zm` 当前高度 64px；Base URL、API Key 容器高度 40px，三个复制/刷新图标按钮的点击区域为 40×40px。
- 显示完整 Base URL，包含协议和实际监听端口。不得硬编码示例端口 `12731`，也不得把所有协议都统一追加成某一个 API 路径。
- Base URL 复制完整值，不复制标签、空格或省略号。
- API Key 默认只显示掩码，不增加明文展示入口。现有后端可以返回掩码及末四位；画板圆点为脱敏示意。
- 复制 API Key 继续由后端直接写剪贴板，前端不接收完整密钥。
- 刷新期间防止重复触发；成功后更新掩码，失败保留原状态并允许重试。
- 刷新替换的是手动接入 Key。旧手动 Key 随之失效；不会改写现有 Agent 配置，也不会刷新供应商凭据。
- 复制成功使用短暂对勾或项目既有成功反馈；失败使用既有通知方式。不能先显示成功再等待接口结果。
- 保留来源数、模型数、Agent 数和接入开关。开关语义继续沿用当前产品逻辑，不能因视觉改版重新定义。

### 3.2 模型来源与最近会话

- 来源卡展示来源名称、凭据类型、模型名及关联会话数量。关联关系以稳定连接标识为依据，不用显示名称匹配。
- 会话卡展示标题、工具、项目、最近活动、真实运行状态及累计 Token。
- 同一来源可以关联多条会话，不能复制来源卡来伪装多个来源。
- 默认画板展示 5 条会话，展开画板展示 8 条作为示意；真实会话总量不得限定为 8 条。
- 默认展示窗口中，运行中会话优先占据前部位置；其余按最近活动补足。展开入口显示剩余最近会话。
- 「展开更多最近会话」在当前区域内展开；收起后回到默认窗口。没有更多内容时不显示无效入口。
- 两栏内容共用滚动容器和坐标系，不能各滚各的，不能让曲线悬停在页面固定位置。
- 区域标题固定在顶部，内容滚动；光线始终连接卡片端口，不覆盖卡片内部文字。
- 页面自身的纵向滚动与主图内部滚动应有清楚边界；在主图边界处遵循项目滚动行为，不强制劫持整页滚轮。

### 3.3 排序与运行状态

- 排序优先级：有可信运行证据的会话在前，其余按最近活动时间从新到旧。
- 相同时间采用稳定会话标识作为最终顺序，避免每次刷新交换位置。
- 会话标识至少由平台与原始会话 ID 组成，不能只用列表序号、标题或项目名。
- Token 更新不是会话重排事件，不能因数值增加持续把卡片搬到第一条。
- 多个请求同时属于同一会话时，按未结束请求集合判断运行状态；结束一个请求不代表整个会话已完成。
- 请求开始、结束、取消及失败必须正确配对，重复或乱序事件不能产生负计数或永久运行状态。
- 仅有会话文件更新时间、最近请求记录或 Agent 在线，不足以断言「正在运行」。
- 没有明确完成证据时保持既有「最近活跃」语义，不擅自改成「已完成」。没有阶段数据时，不从耗时推测「正在思考」或「正在生成」。
- 用户正在查看下方内容时保持首个可见会话及相对位置；不得因为新请求自动滚回顶部。

### 3.4 Token 口径

本次展示的是该会话累计 Token，不是 Agent 今日用量、账号余额或单次请求 Token。取数优先沿用会话线程的权威统计口径，并明确它可能包含该会话通过其他入口发生的消耗，不能标成「仅经网关消耗」。

| 情况 | 展示与处理 |
| --- | --- |
| 四个分项完整 | 普通输入 + 缓存读取 + 缓存写入 + 输出 |
| 已有等价且可信的会话累计值 | 使用该值；不得再重复叠加分项或实时增量 |
| 完整数据且合计为零 | `0 Tokens` |
| 无可信总量，且必要分项缺失 | `— Tokens`，不得把空值当零补齐 |
| 查询失败 | 保留可识别的失败状态；有上次值时标明其状态，不伪装为最新 |
| 数据过期 | 保留上次值并标识过期，不能静默冒充实时值 |

- 小于 1,000 显示整数；其余使用 K / M，最多一位小数。数值采用等宽字体，右侧区域宽度稳定。
- 悬停可以查看未缩写数值；数字更新不改变卡片高度与位置。
- 实时事件、上游流式累计值和会话文件统计必须有明确去重边界。累计值覆盖旧累计值，不能每次收到都作为增量相加。
- 缓存字段必须确认是互斥分项后再相加，避免把已含缓存的输入总量重复计入。

## 4. 曲线与动效规范

| 场景 | 规范 |
| --- | --- |
| 运行中关联 | 2.4px 主线与低透明度柔光；光点从来源向会话移动，一轮 2.8s |
| 结束后的关联 | 220ms 淡为 1.4px 静态细线，停止流光 |
| 会话置顶或位置变化 | 280ms 平滑位移，卡片与曲线端点同步 |
| 展开更多 | 内容高度变化 240ms，箭头旋转 160ms，保持阅读位置 |
| 悬停对应关系 | 140ms 强调关联卡片和曲线，其余曲线轻微减淡；退出 100ms |
| 键盘焦点 | 2px 主题描边；更多入口高度 44px，支持 Enter / Space |
| 减少动效 | 停止流光及重排动画，保留静态颜色、状态文字和对应关系 |

动效必须可以从当前进度被下一次操作接续，不先复位再重播。禁止持续缩放、卡片抖动、频繁闪烁和全属性过渡。

曲线几何更新与视觉移动使用同一布局结果。滚动、窗口尺寸变化、侧栏收起、缩放、展开收起和会话重排后，端口仍需对齐。只有可见的运行中关联播放流光；离屏或窗口隐藏后暂停。Token 更新不能触发全图重建。

## 5. 路由流水：默认每页 10 条

### 5.1 展示和操作

- 默认进入第 1 页，每页固定 10 条，按新到旧排列；不足 10 条按实际数量显示。
- 复用「调用明细」分页：统计、上一页、页码窗口、省略号、下一页、页码输入和跳转按钮。
- 首页禁用上一页，末页禁用下一页；省略号不可点击。
- 输入只接受有效页码范围内的整数，Enter 与「跳转」等效；非法输入保留当前页并提示有效范围。
- 请求期间阻止重复提交；失败保留原页内容和页码，允许重试，不能显示目标页码配旧页记录。
- 没有数据时显示真实空态，不构造「第 1–10 条」或可操作的无效页码。
- 画板中的 846 条和 85 页是样式示例。总数、页数和当前范围必须由真实查询结果计算。
- 这里不增加分类分组，不复用来源分组来改变流水归属。

### 5.2 后端查询与一致性

当前接口只返回最近 20 条，不能在前端把这 20 条切成两页后当作完整分页。开发需要提供目标页记录、每页条数、当前页、总记录数和总页数，并返回稳定的行标识。

排序必须有唯一的次级键，例如以已有自增流水 ID 从大到小，避免相同时间记录重复或漏页。计数与列表需要基于一致的查询范围。

开发建议：一次浏览使用固定查询上界，在翻页期间让新增请求不挤动旧页；显式刷新时重新建立查询范围并回到第 1 页。该建议不新增界面控件，具体查询参数名在开发时确定。即使采用其他方式，也必须证明连续翻页没有新增写入造成的重复或遗漏。

当前后端周期性保留最近约 1,000 条流水，清理是分批执行的，因此暂时可能超过 1,000 条。分页统计只能代表当前保留范围，不能宣称覆盖全部历史。本轮不新增删除策略，也不扩大清理范围；若需要永久保留，另行确认存储策略。

流水列及数据口径：

- 保留时间、Agent、请求模型、实际来源/上游模型、耗时和结果。
- 当前 `duration_ms` 对流式请求是等待上游响应头的耗时，不是首字耗时或整段生成耗时。
- 当前结果为成功、拒绝或失败，不得凭示例画出已经实现多次故障转移的结论。
- 主稿仍有「首字」列名和「自动切换」示例，与当前接口能力不一致，列入第 8 节待确认项；开发前需要同步设计，不能照抄为真实能力。

### 6.1 会话关联的数据要求

现有 `gateway-route-start` 与 `gateway-route` 事件没有直接携带界面会话 ID，也没有累计 Token。不能仅凭同一 Agent、同一模型、同一项目或接近的时间，将请求连接到「最近的一条」会话。

开发需要形成可信的会话聚合结果，至少覆盖：

| 信息 | 要求 |
| --- | --- |
| 会话身份 | 平台与原始会话 ID，稳定且可与会话线程对应 |
| 显示信息 | 标题、工具、项目、最近活动时间及真实状态 |
| 来源关系 | 稳定连接 ID、来源 slug、实际模型，并能区分当前请求与历史关联 |
| 在途请求 | 当前未结束请求集合或等价计数，用于并发运行状态 |
| Token | 可信累计值或完整分项，以及可识别的可用性状态 |
| 数据时间 | 快照时间或等价版本，防止快照覆盖更新的事件 |

亲和键中的请求级 ID、缓存键及令牌兜底不是已验证的会话身份。无法关联时不得连错线或编造会话；对应缺失状态的具体 UI 见待确认项。

现有请求 ID 只在当前进程内递增，不持久化。不得直接把它当跨重启、跨实例唯一的历史标识。启动或重新进入页面时，历史结束流水也不能恢复「当前仍在运行」；需要权威在途快照或已有等价数据源。

订阅适配器内部生成的会话 ID 也不一定等于调用工具的会话 ID。应保留可验证的映射关系，不把内部桥接会话当成另一条用户会话。

已有最近流水接口还被灵动岛使用。新增分页时应保留其使用场景，或同步改完全部调用方；不能只改返回形状导致其他窗口失效。

## 7. 后续开发顺序

1. **数据闭环**：先完成真实请求到会话、连接的关联和进入页面的快照；验证并发、取消、乱序和未知身份。
2. **静态页面对齐**：按 J6-01 替换主图与名称，按 `PA0Zm` 完成单行信息栏，保留管理入口和安全操作。
3. **会话交互**：接入真实 Token、运行优先、默认展示与展开收起，确保不会误连或跳动。
4. **流水分页**：先完成后端准确分页，再接现有分页 UI；验证新增写入及保留范围变化。
5. **动效与验收**：按 J6-03 完成流光、重排及滚动，进行 Pencil 对照与真实桌面检查，再更新模块 J 的实现说明。

数据结构如需新增字段或表，只做可恢复的变更，保留已有连接、统计和原始会话文件。第三方接口的具体语法在真正开发时按项目规范先查询 Context7；本说明不引入新依赖或替代官方 API 文档。

## 9. 验收清单

### 9.1 视觉与操作

- [ ] 主窗口入口、标题和说明使用「统一网关」，内部命令与标识符不做无意义重命名。
- [ ] 对照 Pencil 截图：来源直接连最近会话，主图没有中间模型池节点。
- [ ] Base URL 与 API Key 同行；三个按钮分别执行正确操作，密钥不经过前端明文展示。
- [ ] 原有管理、接线、开关、安全操作和路由流水仍可访问。
- [ ] 默认多条会话、展开收起、两栏共同滚动和右侧 Token 与画板一致。
- [ ] 重排、滚动、缩放与侧栏变化后，曲线端口仍对齐，无裁切和文字覆盖。

### 9.2 数据与状态

- [ ] 同一 Agent 的两个并发会话不会连错来源；同一会话的并发请求不会提前结束运行状态。
- [ ] 开始/结束事件重复、乱序、取消与重进页面均不会永久卡在运行中。
- [ ] 无法验证的会话身份不被「最近时间」猜测替代。
- [ ] 已知零、未知、失败、过期分别表达；Token 与权威会话统计一致且没有重复累计。
- [ ] 刷新手动 Key 后旧 Key 失效；刷新失败时旧 Key 仍有效；Agent 配置保持原语义。
- [ ] 正式桌面取数失败不会回退示例；日志、导出、诊断和事件不包含凭据或提示词。

### 9.3 分页与性能

- [ ] 用 0、1、10、11 条及多页记录验证空态、整页、末页和边界按钮。
- [ ] 验证相同时间记录、持续新增请求和保留范围变化下的翻页一致性。
- [ ] 非法页码不翻页；目标页失败时保留原页；总数来自后端真实保留范围。
- [ ] 原灵动岛的最近流水、活动状态和今日统计没有因接口变更回归。
- [ ] Token 更新不重排卡片，查看下方内容时没有自动跳顶。
- [ ] 减少动效、窗口隐藏和离屏时行为符合 J6-03，输入操作不被动画阻塞。

测试强度按实际修改范围选择。纯格式化和分页边界使用针对性测试；涉及公共数据契约、事件、统计或多个窗口时，补相应后端与前端回归，并进行真实桌面验收。不为本次文档执行产品构建或全量测试。
