# 签到统计卡 A 方案实施计划

目标：实现鼠鼠已选定的紧凑统计卡，不实现 B 的七日签到格。

设计依据：`docs/ui/Jolu.pen` 的「签到统计卡方案 · A 已确认」中 A 的浅深色版本，正式画板 145 / 146。鼠鼠回复 A 已批准布局；本轮将其作为正式统计卡，金额仍由真实数据提供。

## 规则与合约

- 只统计 Jolu 保存的成功签到记录，按真实身份键跨连接去重；完整历史查询不受最近 50 条展示限制。界面注明统计来源，首次无记录显示暂无记录。
- 周按北京时间周一开始，月按北京时间自然月；成功领取的时间用于归属。相同官方周期只计一次，缺周期时按领取日期去重。
- `statistics` 为 `Update` 的可空新增字段：`{has_records:boolean,unit:string,week:{days:number,reward:number|null},month:{days:number,reward:number|null},all:{days:number,reward:number|null}}`。任一已成功记录的奖励缺失时，对应奖励和为 null，不能伪造为零；真正零保留。
- 查询或领取后的同一数据库快照返回统计，失败/未知结果不累计，不改旧账号与历史。新增索引可恢复，无删除迁移。
- 账户额度复用 `useQuota`：仅展示来源已提供的总量和精确剩余，不从百分比推算、不相减伪装官方剩余、不合并重叠额度窗口。WorkBuddy 使用逐资源包原始 `amount_ranges`（含空数组，不回退旧聚合窗口），Qoder 仅知总量时也保留；多窗口分别列明范围。未知、无权限、失败及过期分别显示。
- 签到完成后清理该连接额度缓存并按连接 ID 通知刷新；隐藏页不主动查询。保留当前右侧通知与按钮加载，不恢复页面横向进度条。
- 不提交、切换、重置或创建 Git 工作树；在现有工作区按文件分工，保留全部既有修改。
