# Jolu 统一 AI 工具管理器开发实施计划

> 编写日期：2026-10-21。本文是开发计划，不代表功能已实现或已通过测试。
>
> 执行说明：后续按 `superpowers:executing-plans` 逐项执行，使用复选框记录完成情况。当前仅编写计划；不开始实现，不执行 Git 写入操作，不默认启动多智能体协作。

**目标：** 基于现有 Jolu 项目，完成 Jolu 桌面管理工具，实现供应商接入、账号管理、真实用量、会话与交接、Skills、自动化及独立灵动岛的完整使用流程。

**架构：** 保留 React 前端、Tauri/Rust 本地后端和 SQLite。后端统一负责凭证、采集、查询、文件操作、任务执行与窗口状态；前端负责展示和用户交互。先完成一条真实数据流程，再扩展平台与复杂任务，不把每个窗口做成独立的数据采集端。

**技术栈：** 沿用仓库已有 React 19、TypeScript、Vite、Tailwind CSS、Tauri 2、Rust、rusqlite，以及当前组件、请求和测试工具。此处版本依据仓库清单，不是升级建议；本轮不以升级依赖为前置任务。

**依据：** [Jolu 设计画布](../ui/Jolu.pen)（2026-10-22 起为唯一 UI 依据，灵动岛以其中模块 A2 为准，见根目录 `AGENTS.md`）、本次对话确认的交互、当前仓库代码及既有平台接入计划。`.pen` 仅通过 Pencil 工具读取，不按普通文本文件处理。

## 一、执行结论与范围

现在可以开始开发。第一步不是把全部画板转换成页面，而是统一设计依据、平台能力和接口，再按模块完成真实数据闭环。

本轮优先交付 Windows 桌面版。跨设备同步、团队协作、云端任务执行、移动端、公开 Skills 商店不进入首版范围；后续需要时另立计划，不预先建设服务端账号系统。

前端和本地后端可以并行，但必须使用同一份数据契约。一个模块完成的定义是：界面可操作、真实后端已接入、关键异常可恢复、数据重启后正确保留。

### 1.1 全局约束

- 所有新增代码、配置与文档使用 UTF-8。
- 未经鼠鼠明确授权，不执行 `git add`、提交、推送、分支切换或重置。
- 不覆盖现有工作区改动，不删除旧账号、历史统计和原始会话文件。
- 静态预览可以使用明确标记的示例数据；正式桌面运行不能在错误时悄悄回退到示例数据。
- 未知值、真实的零、能力不支持、查询失败、已有数据过期分别表达。
- 不从 UI、图标、套餐名称推断供应商支持登录、余额、Skills 或自动化。
- API Key 和认证信息留在后端处理，列表只返回掩码；不得进入普通日志、统计导出和诊断报告。
- 应用关闭主窗口固定收起到系统托盘，不恢复已经删除的关闭行为选项。
- 不恢复无必要的模块快捷入口；接管状态保留在本地代理卡片内。
- 实际开发涉及第三方库、SDK、CLI 或认证协议时，先按全局指令通过 Context7 核对文档；特定供应商能力再查其官方资料并记录验证日期。本文不代替该验证。

### 1.2 五个贯穿全程的审查重点

| 风险场景 | 应有行为 | 负责阶段 |
| --- | --- | --- |
| 旧版升级、平台标识变化、应用更名 | 旧数据仍能打开；迁移失败可恢复；Trae 不被改名成 OpenCode | P0、P1、P12 |
| 切换账号或筛选后旧请求才返回 | 旧结果不能覆盖新选择；额度与账号对应正确 | P1、P3、P4 |
| 会话文件重复写入、截断、轮换或编辑 | 不重复计量；压缩检查点不跳过内容；错误可定位 | P4、P5、P8 |
| 额度倒计时结束，但仍不可用或认证过期 | 不直接启动任务；重新验证后再决定等待、执行或要求处理 | P9、P10 |
| 任务运行中崩溃、退出、更新或网络中断 | 不重复启动同一任务；不能确认副作用时不自动重放 | P9、P10、P12 |

### 2.1 必须先解决的平台差异

新 UI 的目标入口为：自定义、Claude Code、Codex、Gemini、Grok、OpenCode、Zcode、Qoder、Workbuddy。

当前 `frontend/src/lib/platformCatalog.json` 和 `frontend/src/types.ts` 包含 `trae`，尚未包含 `opencode` 与独立的自定义入口。开发时必须：

1. 保留已有 `trae` 数据标识，作为历史兼容来源；不把它转换为 `opencode`。
2. 为 OpenCode 增加独立标识和经过验证的适配能力。
3. 自定义接入具有自己的协议类型、名称、Base URL、凭证和模型配置；不能回落为 Claude。
4. 展示名暂按现有代码和素材使用 `Gemini`、`Workbuddy`；将对话中的 `Geimini`、`Wordbuddy` 作为命名核对项记录，不静默重写存量 ID。
5. 一个“AI 工具/平台”、一个“模型提供方”、一个“连接账号”和一个“统计来源”不是同一概念。模型图标跟模型家族绑定，不能直接使用当前工具的图标替代。

## 四、技术边界与数据契约

### 4.1 推荐分层

```text
React 页面与组件
  └─ 视图状态 / 类型化命令封装 / 事件订阅
       └─ Tauri 命令与事件边界
            ├─ 平台与能力目录
            ├─ 连接、认证、账号及模型
            ├─ 来源采集 → 归一化 → SQLite → 统计查询
            ├─ 会话读取 → 压缩检查点 → Markdown 交接
            ├─ Skills 文件管理
            ├─ 任务调度 → 执行适配器 → 运行记录
            └─ 设置、网络、窗口、托盘、更新
```

- 不新增一个仅为本机 UI 服务的独立 HTTP 后端；优先沿用 Tauri 命令。
- 不把密钥、直接数据库读写和 CLI 子进程放在 React 页面。
- 不让主窗口、托盘和每个灵动岛分别扫描文件或重复查询相同额度。
- 既有 `api.ts` 命令继续复用；新增领域模块再分文件，避免一次性全仓库重构。

### 4.2 核心对象

以下对象是需要冻结的业务契约；表中新增名称是计划名称，不代表当前代码已存在。

| 对象 | 必须包含的含义 |
| --- | --- |
| PlatformDefinition | 稳定 ID、展示名、工具类型、能力及不可用原因 |
| Capability | 能力项、支持/不支持/未验证、验证版本/日期；与本机是否已安装分开 |
| Connection | 连接 ID、平台、认证方式、名称、协议、Base URL、凭证引用、模型设置 |
| AccountSnapshot | 连接 ID、姓名/邮箱（可空）、套餐原文、订阅状态、有效期、更新时间 |
| QuotaSnapshot | 连接 ID、可变额度窗口、已用/剩余、重置时间、来源、过期状态 |
| BalanceSnapshot | 币种、账户或 Key 共享范围、余额、来源、查询状态与时间 |
| UsageRecord | 来源 ID、稳定请求标识、时间、模型、Token 分项、费用性质、延迟与原始语义 |
| Project / Session | 稳定项目标识、工作目录、工具、会话 ID、来源、记录文件、能力与状态 |
| SkillInstallation | 工具、全局/项目范围、真实路径、名称、描述、版本/内容摘要、加载状态 |
| HandoffArtifact | 会话、覆盖范围、生成模式、检查点、内容摘要、文件位置、生成时间 |
| AutomationTask | 任务 ID、触发器、固定连接、会话、工作目录、模型/强度、指令、运行策略 |
| TaskRun | 运行 ID、任务快照、状态、时间、进程/恢复标识、结果位置、错误与取消结果 |

### 4.3 通用接口规则

- 保留现有 DTO 的字段习惯；在命令边界统一映射，不让每个页面自行转换。
- 查询结果明确携带更新时间、来源和过期标记；错误具有稳定错误码、中文说明、是否可重试。
- 金额携带币种；真实扣费与估算费用分别存储/标记，币种不同不直接相加。
- 供应商返回不了姓名、邮箱或余额时，字段保持空值；API Key 连接也不能编造“账号邮箱”。
- 分页返回总数、页码和页大小；过滤条件改变回到第一页，刷新保留有效筛选。
- 事件带实体标识和修订序号；前端忽略过期事件和不属于当前筛选的响应。
- 设置采用原子持久化；写入成功后广播，失败不能让多个窗口分别停留在不同值。
- 需要显式保存的网络表单使用草稿；“测试连接”不等于保存，“已保存”不代表网络一定可达。

### 4.4 拟新增的领域接口

实现前在 `docs/specs/2026-10-21-jolu-contracts.md` 冻结字段定义；避免前后端各自起名。

| 拟定接口 | 输入 → 输出 | 使用方 |
| --- | --- | --- |
| `get_platform_capabilities` | 平台 ID → 能力集合与限制 | 供应商、Skills、会话、自动化 |
| `list_projects` | 平台/搜索/分页 → 项目页 | 会话主页 |
| `list_sessions` | 项目/平台/搜索/分页 → 会话页 | 会话主页、新建任务 |
| `get_session_detail` | 会话引用 → 元数据、记录文件、指标、可用操作 | 会话详情 |
| `read_session_range` | 会话引用、范围 → 规范化消息及稳定范围标识 | 压缩服务 |
| `list_skill_installations` | 工具、范围、状态、搜索 → 安装记录 | Skills |
| `preview_skill_import` / `apply_skill_import` | 来源与目标 → 校验预览；预览令牌 → 逐项结果 | Skills 导入 |
| `prepare_handoff` / `generate_handoff` | 会话及生成设置 → 范围/费用性质预览；预览令牌 → 交接文档 | 会话压缩 |
| `create_automation_task` | 已校验任务草稿 → 持久化任务 | 新建任务 |
| `control_task_run` | 运行 ID、允许的动作 → 最新状态 | 自动化列表/详情 |
| `get_network_status` / `test_network_draft` | 当前配置/草稿 → 状态或脱敏诊断结果 | 网络设置 |

现有连接、模型获取、统计和设置命令优先复用，P1 只在现有接口无法表达时扩展。

## 五、开发流程与依赖

```text
P0 基线与能力核对
  → P1 数据契约与兼容基础
  → P2 应用框架与基础设置
  → P3 供应商与账号真实闭环
       ├→ P4 用量统计 → P5 会话管理 → P8 会话交接
       ├→ P6 Skills
       └→ P7 灵动岛
  P3 + P5 → P9 手动执行与持久化任务（使用所选 Skills 时另依赖 P6）
  P8 + P9 + 可靠额度能力 → P10 额度恢复自动执行
  P2 + P3 + P4 → P11 完整设置与网络
  所有发布范围内模块 → P12 联调、迁移、安装与发布验收
```

依赖满足后，Skills、灵动岛和部分设置可以独立推进；同一模块仍遵循“接口 → 后端真实数据 → 前端联调 → 验收”。不以做完所有静态页面作为前端完成标准。

每阶段先记录失败场景，再实现最小完整路径，最后验收。小型样式修改只做一次针对性检查；迁移、统计、文件写入和调度需要业务测试。每阶段完成后记录文件、验证结果和遗留限制，不自动提交 Git。

**重点测试：** 任务重复提交、重复事件、外部进程丢失、退出码不为零、取消竞态、目录不存在、身份改变、Skill 文件变化、重启后残留运行状态、每日任务时区/夏令时与单次触发去重。

**验收：** 先在隔离测试项目执行，再在授权目录验证；能从任务结果回到目标会话，且不会产生第二个重复运行实例。

### P10：额度恢复后继续执行

**产出：** 任务可以持久化等待额度，确认恢复后在指定上下文继续。

**文件：** 扩展 `backend/src/automation/scheduler.rs`、`runner.rs`；新建 `quota_wait.rs` 与对应测试；扩展前端任务等待状态和错误处理。

**输入/输出：** P9 任务状态、可靠额度能力、P8 交接文档（跨工具场景） → 可恢复的等待与执行流程。

推荐状态流：

```text
草稿 → 已排队 → 运行中 → 已完成 / 失败 / 已取消
                 ↓
              等待额度 → 重新验证 → 已排队
                 ↓          ↓
              用户暂停    仍等待 / 需要处理

应用异常退出后的运行记录 → 中断待确认 → 查询工具状态或由用户恢复
```

- [ ] 区分额度耗尽、短时限流、余额不足、认证过期和网络失败，不把所有 429 或失败都归为额度等待。
- [ ] 保存等待原因、重置参考时间、下次检查时间、连接与会话快照；关闭主窗口不丢失等待。
- [ ] 额度恢复任务默认只执行一次；支持选择执行中耗尽后是否等待续跑。高级设置覆盖等待截止时间和队列规则；选择不限等待时间时仍可暂停或取消，达到截止时间后转为需要处理，不继续占用执行队列。
- [ ] 倒计时结束只触发重新查询，确认可用后才入队；缺少可靠额度查询时显示限制，不声称“已恢复”。
- [ ] 尊重来源的重试时间并退避，多个任务共用同一连接的额度查询；不通过连续模型请求探测额度。
- [ ] 同一账号的多个等待任务恢复时按队列调度，避免同时抢额度；入队及领取运行具有幂等键和互斥控制。
- [ ] 应用重启后先恢复队列并核对正在运行的任务，再检查等待条件；计算机休眠期间不承诺后台准点执行。
- [ ] 错过普通定时任务默认不重复补跑；额度等待任务唤醒后重新验证。是否补跑普通任务需另行明确策略。
- [ ] 崩溃发生在外部操作之后但结果落库之前时，不自动重放；标记需要确认，优先查询工具会话/进程状态。
- [ ] 不静默切换账号、模型或工具。跨工具继续由用户明确选择，目标通过 P8 交接文档获得上下文。
- [ ] 恢复执行、完成、失败通知遵循免打扰；运行日志仍可查看。

**重点测试：** 倒计时到零仍无额度、认证过期、没有重置时间、429 短时限流、多任务同账号竞争、休眠/唤醒、重复回调、运行中崩溃。

**验收：** 隔离环境模拟“耗尽 → 等待 → 重启 → 恢复 → 执行一次”；另用真实来源验证可支持的查询和恢复能力。模拟通过不等于所有平台都支持。

### P11：完整设置、网络和数据管理

**文件：** 修改 `frontend/src/views/SettingsView.tsx`、`hooks/useSettings.ts`、`backend/src/settings.rs`、`proxy.rs`、`proxy_config.rs`、`data_files.rs`、`updater.rs`；新增 `frontend/src/components/settings/GeneralSettings.tsx`、`AppearanceSettings.tsx`、`NetworkSettings.tsx`、`DataSettings.tsx`、`NotificationSettings.tsx`、`AboutSettings.tsx`；快捷键及应用代理按能力验证结果增加后端模块。

**输入/输出：** P1 设置契约、P2 窗口、P3 连接、P4 数据、P9 任务状态 → 持久化偏好与可恢复操作。

- [ ] 常规：默认页面、刷新、全局快捷键。冲突时保留原快捷键；取消录入不改配置。

- [ ] 代理首次接管和运行中改端口展示影响预览。失败回滚；应用异常退出后下次启动检测残留接管配置并提供恢复。

- [ ] 更新检查、下载、校验和重启分开；运行任务尚未处理时不强行安装，失败保留当前可用版本。

**重点测试：** 快捷键冲突、主题写入失败、端口被占用、代理不可达/自循环、清理后重扫、导入重复、更新中断、运行任务与重启冲突。

**验收：** 设置重启后保留；主窗口、托盘和灵动岛状态一致；所有新增选项都有真实后端或明确的不可用状态。

## 八、里程碑、排期与完成标准

| 里程碑 | 包含阶段 | 用户能完成什么 | 通过后再进入 |
| --- | --- | --- | --- |
| M0 开发基线 | P0–P1 | 明确唯一设计、能力和兼容规则 | 大规模页面改造 |
| M1 可用应用框架 | P2 + P3 首条闭环 | 启动 Jolu、添加一个真实连接、读取状态 | 扩展供应商与数据页面 |
| M2 日常管理版本 | P3–P7 的发布范围 | 管理账号、查看用量/会话、管理 Skills、使用灵动岛 | 交接与任务执行 |
| M3 可交接和执行 | P8–P9 | 导出可复用上下文、在指定会话执行任务 | 自动恢复调度 |
| M4 自动续跑版本 | P10 + P11 | 等待额度恢复并可靠续跑，完成设置与诊断 | 安装候选版 |
| M5 发布候选 | P12 | 安装、升级和完整工作流稳定可用 | 正式发布 |

不根据 132 张画板直接承诺固定天数：其中很多是状态和主题副本，认证、CLI 执行与额度查询的不确定性反而决定工期。P0 完成后，按实际团队人数、已验证能力和代码复用程度排期；将每阶段拆成可独立验收的小任务，分别估算开发、联调和回归，不把等待真实账号验证算成已完成。

### 8.1 每个任务完成时必须交付

- [ ] 对应的前端、后端和配置变更，而不只是静态页面。
- [ ] 数据与接口说明，以及新增能力/仍有限制的范围。
- [ ] 相关成功、空、加载、失败、禁用状态。
- [ ] 必要验证的实际结果；未验证项明确列出。
- [ ] 独立改动总结：改了什么、为什么、核心逻辑、验证结果、迁移/回归风险。

### 8.2 不应提前宣布完成的情况

- 页面使用 mock 看起来完整，但桌面后端未接入。
- 某个平台只能显示“暂不支持”，却被计入完整适配。
- 定时器到了就自动执行，没有重新查询额度。
- 压缩生成了 MD，但没有记录覆盖范围和检查点。
- Skills 在列表消失，却没有核对真实目录和其他副本。
- 前端显示已切换账号，实际 CLI 仍使用旧身份。
- 新版能安装，但旧数据、更新渠道或代理恢复没有验证。

## 九、建议首先执行的工作包

第一批只进入 P0–P2，并在 P3 中选择一条可验证连接做完整闭环：

1. 整理现有能力与设计差异，确定灵动岛基线。
2. 统一平台标识、自定义协议、能力状态和迁移规则。
3. 改造主导航、主题、启动页与托盘唤回，保持旧功能可运行。
4. 打通一个真实供应商账号或自定义 API 连接的添加、读取、模型获取和刷新。
5. 接入同一连接/来源的用量查询，核对真实结果与失败反馈。
6. 完成这一批验收后，再扩展其他供应商和会话、Skills、自动化。

这样能尽早确认整套 UI、数据契约和本地后端是否匹配，同时避免完成大量静态页面后才发现认证与执行能力不成立。
