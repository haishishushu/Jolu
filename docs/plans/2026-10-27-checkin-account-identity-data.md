# 签到账号识别与完整数据实施计划

目标：取消订阅账号手填名称，显示真实授权账号；宽屏一行四张供应商卡；补齐官方可查询的签到统计和精确额度，并提供逐账号删除。

技术：沿用 React / TypeScript、Tauri / Rust 与 SQLite；不新增依赖，不进行 Git 写操作。鼠鼠已明确授权自行决定并完成，沿用现有 A 统计卡，Pencil 同步变更。

## 需求与边界

- 订阅授权/本机检测表单显示只读「账号」，不再要求填写连接名称。保存名称由后端已验证账号派生。API Key 和自定义服务名称继续用于区分服务，本轮不改其语义。
- 签到卡显示官方账号标识，不能继续把旧自定义连接名当账号；已有连接及历史不因显示方式变化而重命名或丢失。
- 宽屏每行四卡，窄屏降至三、二、一列，保证卡内数据可读。
- 逐账号删除使用现有连接删除接口及确认交互；当前签到页在领取/保存期间禁用删除。其他入口在已发送领取后删除连接时，仍保存原身份的已发生领取记录，页面结果按身份核验裁剪。历史不丢失，不能误删同供应商其他账号。
- 官方可用的签到历史/汇总及额度全部读取并按来源展示；不能把活动累计当终身累计，不能把已用当剩余，也不能为了填满界面补造数字。缺能力或字段时展示准确原因，并区分官方与 Jolu 记录。
- 本轮只读验证真实接口，不重复领奖，不回显凭证、设备值、UID或原始响应。

## 任务与分工

- [x] 账号表单：复用现有检测结果，后端由验证身份生成保存名称；添加合成授权/同身份去重回归。
- [x] 官方数据：核对三平台官方代码及响应；WB 接官方返回日期与本期累计，Trae 接汇总、逐包与明确计算可用，Qoder 维持当前轮次与本机历史并标明范围。缺少的完整历史不补造。
- [x] 页面：显示真实账号、增加删除与确认、四列响应式；同步 Pencil 正式画板 145–148 和订阅表单。
- [x] 验证：红绿回归、前端 244 项、后端 663 项、类型/生产构建、三组合成 UI 及只读真实接口、独立审查均完成；详见同日验收记录。

## 验收重点

未知与零分别表达；官方历史覆盖范围不足时不声称全历史；原工具换号/连接改变不串数据；删除只针对指定连接且保留记录；订阅保存不再依赖用户名称；不足四卡时不造空账号；页面离开后不新发额度查询。
