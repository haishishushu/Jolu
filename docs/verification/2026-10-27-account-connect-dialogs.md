# 账号连接弹窗与多账号修复验收

## 需求与根因

鼠鼠要求账号管理的「添加账号」和一键签到的「去连接」在当前页复用供应商的连接表单，并修复 Trae 授权和同供应商多账号问题。

原账号管理按钮只切换到供应商连接页签，签到按钮跳转供应商页，且没有传入准确版本；已有签到账号的卡片缺少新增入口。浏览器授权共用流程还将额度查询成功作为可保存条件，导致官方身份有效但额度不支持或临时失败时无法连接。重复授权没有按稳定身份更新已有连接。Trae 的令牌期限解析遗漏了官方绝对期限落后时使用毫秒时长的处理。没有鼠鼠失败当次的原始响应，不能断言这些问题中的任意一个是此次失败的唯一原因。

## 改动总结

- 新增 `AccountConnectDialog.tsx` 封装同一连接表单和保存规则。供应商、账号管理、签到三个入口共用；签到准确预选平台和版本，保存后在原页刷新，不改变当前导航或账号页签。
- 四个可手动签到版本的卡片增加加号。浏览器授权的不同账号独立保存与显示；同平台同版本同官方身份重新授权更新原连接，保留名称、创建时间及历史，并按最终连接 ID 重新加密绑定。WorkBuddy 身份还包含企业边界。
- WorkBuddy、Qoder、Trae 的浏览器授权先执行本次官方身份请求并比对稳定身份，再独立查询额度。额度不支持、无权限、限流或失败可分别显示；真实未授权仍然拒绝。其他供应商授权规则不扩展。
- Trae 使用官方 `GetUserInfo` 实时核验个人身份，拒绝变更 UID、失效期限和错误响应；补齐官方 `TokenExpireDuration` 毫秒兜底，不为缺失或无效期限编造时长。
- 保存时以即时引用阻止同帧重复提交，并冻结输入、切平台、重授权和关闭，避免旧保存完成后取消新授权、关闭新草稿。失败保留输入。独立审查发现此竞争后，先写失败回归，再修复通过。
- Pencil 已恢复连接；通过 MCP 同步 133–138 的入口、多账号示例与规则，新增 139–140 当前页共享弹窗，浅深色截图与运行截图对照。未通过文本方式读取或编辑加密设计稿。
