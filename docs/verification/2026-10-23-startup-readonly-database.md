# 启动界面只读数据库报错修复

## 复现与原因

- 在实际 Tauri 桌面主面板的「灵动岛」页看到 `连接列表读取失败：attempt to write a readonly database`。
- `list_connections` 使用 `DbRead`，数据库连接通过 `db::open_reader` 设置了 `query_only=true`。
- 连接列表此前为旧订阅账号补充邮箱时执行了 `UPDATE`。当旧记录缺少邮箱、且保存的凭证与本机登录匹配时，列表读取就会误写并失败。
- 网络诊断也复用连接列表查询；自动化账号列表同样复用这段逻辑。

## 改动

- 连接列表保持纯读取。旧账号的未知邮箱只在返回 DTO 中按凭证匹配补充，不在查询中写数据库。
- 保留数据库只读保护；不修改数据文件权限，不隐藏查询错误。
- 已保存邮箱优先保留。未匹配、缺少凭证和 API Key 连接不补充邮箱；原始凭证始终不进入前端 DTO。
- 新增隔离临时数据库回归测试，使用正式的 `db::open_reader`，覆盖匹配、已保存身份、不同账号、API Key、缺少凭证以及 DTO 不包含原始凭证。

## 验证

- `cargo test --manifest-path backend/Cargo.toml connections:: --lib`：31 项通过。
- 修复后的实际桌面应用重新启动，灵动岛页已正常显示连接，原只读数据库错误消失。
- 后续逐页导航验证遇到 Windows 锁屏，等待解锁后继续；尚未将其他页面记录为已通过。
- 此阶段只修改后端查询和回归测试，没有调整界面样式或设计稿。
