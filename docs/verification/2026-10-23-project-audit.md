# 全项目可靠性与性能审查（2026-10-23）

本轮范围：页面读取的异步竞争、共享查询与缓存、只读数据库、隔离验收边界和明显阻塞界面线程的计算。账号管理与更新链路由并行任务单独验收。本记录不代表所有产品功能已通过真机验证。

## 已发现并修复

1. **Skills 详情串文件内容**：连续切换文件时，较慢的旧请求会覆盖新文件；旧请求失败也会覆盖当前成功结果。新增 `observeActiveRequest`，effect 清理后丢弃成功与失败回调，应用于 Skill 详情和附属文件读取。可控 Promise 回归先复现两个失败，修复后通过。
2. **自动化任务详情显示旧账号/旧成功额度**：额度状态未绑定连接 ID，改账号后可能临时沿用上一账号；后续查询失败仍可能显示此前成功结果。现在结果带连接 ID，成功与错误合并保存，错误清掉旧额度，切换账号立即视为未加载，迟到结果由取消保护丢弃。原先“成功后旧错误仍显示”的初步推测经渲染分支核实不成立，未以此作为缺陷依据。
3. **Skills 保存期间丢失后输入草稿**：保存请求发出后输入区仍可修改，成功回调退出编辑器，后输入内容未保存。保存期间统一禁用名称、描述、供应商、范围、正文、模板、保存后启用等入口；保存函数增加重复调用保护。
4. **大文件差异比较阻塞**：原 LCS 只限制单边 5000 行，5000 × 5000 仍分配约 50 MB 矩阵，且同步占用界面线程。新增总计 100 万单元格预算（矩阵约 2 MB），超限沿用已有整段替换方式，仍保留共同首尾；小范围变动继续精确比较。

5. **会话文件读失败被当作成功**：`read_lines` 曾吞掉打开失败和中途行读取错误，消息页可能返回部分正文，交接流程可能据此生成不完整材料。现在返回 `Result`，消息、交接生成和重新排版均传播读取错误；隔离模式显式拒绝直接读取。新增合成 UTF-8 损坏源文件回归，修复前真实失败、修复后通过；同时检查正常读取和文件不存在的错误路径。

6. **离开会话后迟到错误打扰新界面**：SessionDetail 卸载时未使请求序号失效，更早消息失败仍会弹全局提示。现在卸载递增序号，分页成功、失败、收尾均核对归属；重新读取重置分页忙碌状态。

7. **设置同步被旧请求覆盖**：用实际 `useSettings.ts` 的窗口级函数注入可控 Promise，复现旧读取错误盖住新推送、推送恢复不清旧错误、较旧并发读取提前结束加载。现在读取成功/失败/收尾同时核对请求序号与推送版本，成功推送清除读取错误与加载状态。补充新成功先返回、旧成功后返回的逆序测试。

8. **主窗口首开捆绑全部页面代码**：七页静态 import 改为模块顶层创建的 lazy 页面，首屏仅请求当前页；各页首次加载复用对应的 `LoadingSurface`，完成后沿用内容淡入。边界只包内容，侧栏与页头继续可操作。渲染异常可局部重试；资源加载失败明确提供“重新加载应用”，不会自动重载，也不会伪称局部重试。Edge 生产故障注入证实：仅重建 lazy 时同一失败 import 被浏览器缓存，并未再次请求；最终按官方支持的整页重载方式恢复，仅响应用户明确点击。

## 性能测量

主窗口 chunk 减少约 89%，这是产物体积变化，不能直接宣称启动时间减少 89%。公共主入口仍为 270.75 kB（gzip 85.15 kB），按需加载的页面仍需解析自身及共享依赖。该改动的直接证据是首开网络记录不再加载无关页面，以及生产产物中七个独立页面 chunk。

文档核对：Context7 先解析 React `/reactjs/react.dev` 再查询 lazy/Suspense 与错误边界；按需页面须保持稳定 lazy 声明、拒绝结果由错误边界处理。资源错误恢复再解析 Vite `/vitejs/vite` 并查询 `vite:preloadError`，官方说明旧浏览器可能缓存模块失败、需要重载。[React lazy](https://react.dev/reference/react/lazy)、[Vite 加载错误](https://vite.dev/guide/build.html#load-error-handling)。
