# 本地登录与系统默认浏览器授权

日期：2026-10-26。续接全部供应商查询补齐。鼠鼠明确要求双入口、真实查询以及全部浏览器授权使用电脑默认浏览器。

## 改动总结

- 连接弹窗保留“读取本地登录信息”和“浏览器授权”两个入口。WorkBuddy / Qoder 的国内、国际区域同时约束本地检测、保存与浏览器登录，不能跨版本读取。
- 全部浏览器授权经统一 `open_default_browser` 调用操作系统默认处理器，不指定浏览器、不创建内嵌授权窗口。未接入协议的平台明确禁用浏览器入口，不能只开放按钮。
- Qoder 国内/国际分别读取对应桌面应用的 v10 safeStorage 文件；校验本机到期时间与用户标识，调用对应区域的真实 usage 接口。国际版仅在桌面文件确实缺失时保留原 CLI 查询，不用过期/损坏桌面登录触发跨来源回退。
- Qoder 浏览器流程使用官方设备 PKCE / nonce；WorkBuddy 使用官方 state → token → account 轮询。两者先取得独立账号，再验证真实额度，前端才允许保存。
- 新授权先留后端内存，保存时用 Windows 当前用户 DPAPI 及连接 ID 封存。前端、列表、错误均不返回令牌；浏览器连接查询使用自己的授权，不替换为本机账号。取消、超时、切换和迟到响应阻止保存。
- WorkBuddy 慢网络创建 state 在后台执行，先返回授权 ID，使取消能及时生效；打开默认浏览器前再次检查取消和超时。
- 浏览器账号的暂停恢复、启用与获取走自身授权验证。本地探测、CLI 调用和网络查询移到数据库锁外的阻塞线程，登记函数仅写库；重复登记保留旧连接的暂停状态和历史。

## 原因与真实证据

WorkBuddy 的旧令牌可以解密且记录有效期在未来，但官方账单仍拒绝 401。鼠鼠在原工具重新登录后，固定官方账单端点返回 HTTP 200 / code 0。Rust 真实查询成功，输出仅为 `state=ok windows=1`。此前出现一次 Rust 查询失败，重新执行通过；没有足够证据说明网络失败根因已经消除。

Qoder 国内版旧登录已过期，真实接口返回 401。鼠鼠重新登录后，国内 usage 端点返回 HTTP 200；Rust 真实查询输出 `state=ok windows=3`。

WorkBuddy 未登录的官方授权协议探测：创建 state 返回 HTTP 200 / code 0；授权地址主机为 www.workbuddy.cn，路径 /login；随后未登录轮询返回 HTTP 200 / code 11217。没有输出 state、完整授权 URL、令牌、账号正文，不发送模型请求。

协议依据是本机官方安装包：Qoder `resources/app.asar` 的 main 登录与 usage 逻辑；WorkBuddy 国内及国际安装包的 `cli/product.json`、`main/dev-env-override.js` / `main/common.js`。Tauri opener、安全存储和窗口 API 在实现前已查询对应文档；不将 WorkBuddy 面向开发者的公开 OpenAPI OAuth 当作账单登录授权。
