# 2026-10-23 局部操作反馈验收

## 排查结论

审查七个主页面、查询 hooks、设置存储、供应商卡片及公共动效。React 重新计算本身不等于页面刷新；本次修复的是可见的联动禁用、加载提示和重复过渡。

- 设置与主窗口灵动岛配置共用 saving，保存一项导致同页无关控件变灰。改为字段级忙碌状态，跨字段写入串行执行，避免组合配置读改写互相覆盖。代理配置内相互依赖的控件仍作为一组锁定。
- 连接列表每次重读都置 loading，连接数量随之被清空。已有快照（包括空列表）的后台重读不再进入首次加载状态。
- 用量、会话、自动化把后台事件/轮询和手动刷新混用。新增 revalidate 与 refreshing，将后台同步和按钮反馈分开；已有数据继续保留。
- 自动化内容过渡原本依赖四份查询状态，隐藏查询首次返回也会重播当前区域。现在仅依赖当前路由展示的数据。
- Skills 扫描按钮仅在主动扫描目录时显示忙碌；账号卡片刷新按钮仅在自身点击时转动。

## 验证

- TypeScript 类型检查通过。
- 前端纯逻辑测试 185/185 通过。
- `node scripts/acceptance/local-feedback.cjs`：隔离浏览器 mock API，验证后台/手动刷新分离、空列表后台同步稳定、字段级锁定、不同字段依次保存、失败后队列继续和未提交输入保留。测试不调用真实后端、账号或 CLI。
- 浏览器预览七个主页面依次切换，无运行时错误。
- 本轮不改变布局、颜色及浮动灵动岛展示；未宣称覆盖真实桌面每种网络及后台任务状态。

## 后续实现约束

首次无数据才显示骨架；后台更新保留已有内容。操作反馈绑定发起操作的按钮/记录。仅在数据确实相关时同步其他区域，不能用整页 loading 表示单项保存。需要防止冲突的同一业务操作仍应禁止重复提交。
