# A 账号统计卡验收

## 本轮范围

鼠鼠回复 A，确认紧凑账号统计卡。实现依据为 `docs/ui/Jolu.pen` 的「签到统计卡方案 · A 已确认」及正式画板 145 / 146。每个账号显示周/月签到天数与奖励、累计奖励、对应官方额度范围的总量和可用量；保留顶部账号入口、原地连接弹窗和右侧通知，不恢复刷新或领取的页面横向进度条。

## 数据口径与实现

- 后端 `checkin_stats.rs` 读取当前真实身份的完整成功领取历史，不受最近 50 条记录列表限制。相同官方周期跨连接去重，无周期按北京时间领取日期去重；一天多次有效领取可累加奖励，签到天数仍只计一天。
- 周从北京时间周一开始，月为北京时间自然月，按实际领取时间归属，只计截至查询时刻的记录。非成功记录不计入；真实零保留，任一奖励未知时对应奖励和未知，混合单位不累加金额。
- `Update.statistics` 与领取落库使用同一数据库快照；统计损坏不把已保存的成功领奖改成失败。后置身份变化或数据库快照核验失败时，页面身份和统计一起清空，历史记录仍归原身份，不修改旧账号及历史。
- 额度复用现有查询 hook。WorkBuddy `amount_ranges` 逐资源包保留官方原始 total / remaining 与精度，不能使用旧窗口的推算或合并值；空数组也不回退。仅知总量或剩余时保留已知项，另一项为 null；任一包不完整时不返回误导性的旧聚合窗口。Qoder 仅知总量时仍保留，套餐与加购分别列出。其余窗口只显示明确给出的总量与精确剩余，不从百分比反推或相减。
- 手动刷新先更新已核实身份的额度缓存，再应用该身份的卡片；领取后失效缓存并按事件中的连接 ID 刷新。切页或卸载后不新发额度预热请求；身份变化重挂额度组件，不能继承旧身份数据。查询暂时失败可保留上次成功值，但明确标过期及失败原因。

## 验证限制

统计来源仅为 Jolu 已保存的成功领取记录，官网或其他工具历史不能由当前签到状态重建；没有记录显示「暂无记录」，缺数额显示「—」。本轮不更改平台能力，不将合成 UI 和内存数据库测试当作真实多账号领奖结果。Trae 国内真实网页授权至保存与只读状态的既有记录，以及第二个真实账号尚缺登录样本，仍见 `2026-10-27-account-connect-dialogs.md`。

本轮未执行 Git 暂存、提交、推送、切换、重置或工作树创建。
