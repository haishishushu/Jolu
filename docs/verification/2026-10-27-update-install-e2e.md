# 检查更新与安装器真机验收

日期：2026-10-27。范围：自定义 NSIS 模板（固定安装路径、无目录页）、启动检查与后台下载、页头绿色版本按钮、被动安装与自动重启。做法见 `scripts/release/local-update-e2e.md`「真机安装与更新」。

## 结论

- 首次安装向导：欢迎页 → 正在安装 → 安装完成，中间没有选择目录页，安装到 `%LOCALAPPDATA%\JoluE2E`（正式包为 `%LOCALAPPDATA%\Jolu`）。
- 0.1.0 启动后立即请求 `latest.json`，发现 0.1.1 后自动下载安装包并通过签名校验，期间不弹窗。
- 页头出现绿色版本按钮：文字 `v0.1.1`，底色 `rgb(6, 193, 103)`（`jolu-accent`），文字 `rgb(7, 27, 16)`，可访问名称为「安装 v0.1.1」。
- 点击后应用退出，安装器以被动模式运行，只显示进度，按钮不可点，不显示路径；约 3 秒后应用以 0.1.1 自动重启。运行中的应用和卸载注册表 `DisplayVersion` 都报告 0.1.1，页头恢复为普通的「检查更新」按钮。
- 更新后的应用静置 60 秒内没有任何检查请求，定时检查没有异常的频繁请求。
- 共完成两轮 0.1.0 → 0.1.1 更新：第一轮在测试过程中被手动点击，第二轮由脚本完成并截图。

## 环境与隔离

- Windows 11 家庭版没有 Windows Sandbox，因此在宿主机上使用改名的测试包：`JoluE2E` / `jolu-e2e.exe` / `dev.ningz.jolu.e2e`，由测试私钥签名，更新端点为本机 HTTP 服务。
- 测试包为 debug 构建，主动启动时带隔离目录；安装器重新拉起时依靠临时用户级 `JOLU_TEST_DIR`。被手动启动的测试应用只在自己的 `dev.ningz.jolu.e2e` 目录写入数据，开机自启项未被改写。
- 卸载钩子按固定名称删除 `Run\Jolu`（开发者自己的自启项），测试中已按备份恢复。清理后核对：测试安装目录、卸载注册表项、桌面与开始菜单快捷方式、用户级 `JOLU_TEST_DIR`、测试数据目录、测试进程和端口均已不存在。
