## 已修复：Skills 覆盖导入损坏当前安装项

原路径为 `import_with → backup_dir_tree → remove_dir_all(dest) → copy_dir(source, dest)`。存在两个在隔离临时目录中实际复现的问题：

- 来源就是已安装目录时，删除目标同时删除来源。随后 `copy_dir` 重新创建空目录并读取它，返回成功，因此界面会报告导入成功，而 `SKILL.md` 已消失。
- 来源附件不可读取时，旧目录已经删除，后续复制报错会留下空目录或半成品；旧正文与附件只能从备份手动找回。Windows 测试以独占共享模式打开合成来源附件，稳定复现真实文件读取失败，没有修改 ACL 或真实 Skills。

修复后的顺序：

1. 解析来源和目标的真实路径，拒绝相同目录及互相包含的目录。
2. 在目标父目录创建独占暂存目录，先完整复制来源；目录枚举错误直接传播，不再用 `flatten()` 静默略过。
3. 复制完成后备份旧目录，再通过同盘重命名交换目录。
4. 交换失败时恢复原目录；若恢复也失败，保留原目录的暂存位置，并在错误中给出原目录和备份位置，避免清理掉恢复材料。
5. 交换成功后清理暂存目录。原有启用/停用状态规则不变。

这是函数执行期间的错误恢复，不宣称是跨进程崩溃事务。若进程恰在两次重命名之间终止，旧内容仍在暂存目录与备份目录中，但本轮没有加入启动时自动恢复机制。

## 已修复：自动化编辑污染已有运行与历史

`update_task` 与界面说明写「编辑仅影响后续执行」，但 `start_run`、`finish`、`startable` 和额度等待查询继续读取当前任务配置。编辑等待或执行中任务的账号、平台、目录、提示词或自动续跑选项，会影响已有运行后续调度/续跑。`RUN_COLS` 还从当前任务 JOIN 名称、平台、连接 ID，同时保留运行表里的旧 `account/model/session_id`，历史展示可能混合新旧信息。

按已有明确规则「编辑仅影响后续执行」完成修复：

- `automation_runs` 新增可空 `task_snapshot` 列。创建运行时将完整任务参数与运行在同一个 INSERT 中保存；新运行使用编辑后的配置，已有排队、等待、执行中运行和续跑使用原快照。
- 工具、账号 ID、模型、工作目录、提示词、Skills、等待截止、串行队列和自动续跑均以快照为准。队列占位、同目录互斥、额度检查与历史筛选不再被修改后的任务重定向。暂停/取消/任务是否仍启用继续读取实时任务状态。
- 运行详情的 `task` 返回该运行快照；任务编辑页面仍读取当前任务。运行标题、工具、账号归属及概览执行提示不再混入新任务参数。
- 旧运行没有保存过这些字段，不能用当前任务反推。迁移只添加可空列，不猜填历史；保留原运行 ID、账号显示名、模型、会话、结果与事件。旧活动运行转为 `attention/snapshot_missing`，事件记录迁移前状态和原因，禁止自动认领、自动额度等待和手动原地重试。用户可核对配置后创建新任务；旧历史仍可查看。重复迁移/恢复不会重复添加提示事件。
- 前端纯逻辑 `toolName/shortTool` 对未知工具返回既有占位「—」，避免猜作 Claude；运行 DTO 明确允许 `unknown`，没有更改组件布局。

### 最终复审补充：详情展示归属与迁移后的计时

复审发现后端执行已经使用快照，但任务详情仍从当前可编辑任务展示目录、指令、账号额度和续跑选项。补充 `TaskDetail.execution`：有活动运行或最近运行时返回该运行快照；从未运行时返回当前任务；旧快照缺失返回 null。`TaskDetail` 的执行字段、额度查询与 `AutomationView` 的账号选择统一使用此来源，关联会话跳转使用相应运行的工具与会话 ID，编辑操作仍使用当前 `item`。未知快照使用既有「—」占位，不发账号额度查询、不把未知当成未开始/账号已移除，不开放未知平台的会话跳转；重新排队沿用现有禁用按钮状态。
