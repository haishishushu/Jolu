# 账号空白、统计汇总与趋势断线修复

## 原因与改动总结

1. 账号页的定高列表依赖父级高度。真实入口通过 createLazyPage 的 ReadyPage 包裹，外层只有 min-width，没有传递高度，列表实际高度为零。给懒加载页面增加显式 fillHeight 选项，供应商入口启用；其他页面保持自然滚动。加载态同样传递高度。
2. 概览使用严格汇总，任一原生请求缺 Token 就返回整体未知，已知 Claude/Codex 数值因此被隐藏。保留严格字段，额外返回已知 Token 合计、已知记录数，以及同一批完整输入/缓存记录的缓存命中率与覆盖次数。前端显示“已知 Token”和缺失次数；部分数据不做完整总量环比，模型占比使用对应已知合计。全部未知仍为未知，真实零保留。未计价费用不填零或推测单价。
3. 鼠鼠要求今日用量曲线连续。原 smoothPath 遇 null 会开启新段，导致断线。改为保留时间索引、跨过未知点连接已有点，控制点限制在相邻点范围内；未知区间不生成假值，悬浮框保留未提供说明。全部未知不画线，前后未知不延伸曲线。

## 验证

- 修复前：包含真实懒加载外层的账号布局测试复现列表高 0、可见卡片 0；统计后端测试复现已知合计缺失；连续曲线测试复现两个 M 段。
- 修复后：account-cards.cjs 改为挂载真实 MainPanelWindow 和整个供应商入口，1280×900 / 1920×1080 均首屏八张，后续滚轮可见；十四张卡片逐项详情、六模型额度和到期状态验证通过。
- usage-overview.cjs：已知/未知混合、全未知、真实零、缓存覆盖、模型占比、四条线跨缺失点连续和悬浮提示通过。已查看输出截图。
- 后端 usage_stats::tests：7 项通过，含已知合计与同批缓存计算回归。前端纯逻辑与共享状态 212 项通过；曲线针对性 8 项在追加修改后通过。
- 类型检查、前端构建和差异空白检查通过。
- 真实桌面概览已经读取到约 2.07 亿已知 Token 和 95.9% 缓存命中率，且标记 1 次缺失记录。数字随当前会话增长，不作为固定验收常量。真实账号页输入被窗口最小化和用户正在使用窗口打断；首屏与详情覆盖来自完整真实组件、合成桥接的检查。
