# 签到账号、四列布局与官方数据验收

## 改动总结

鼠鼠要求名称改为账号且免填、每行四卡、查询全部可用数据，随后补充账号可删除。本轮沿用 A 统计卡，调整订阅连接表单与签到卡显示，并补齐官方当前确实提供的字段。

- 订阅表单显示只读账号，检测/授权通过即可保存。后端忽略手工名称，以同一已核实凭证中的账号派生名称；无邮箱/用户名时用稳定身份指纹，不把 UID、Token 或设备值当标签。API Key/自定义服务名称不改。重授权同身份继续复用 ID、保留原创建时间及历史。
- 签到卡显示真实账号，旧任意连接名称不充当账号。状态结果同时返回与身份同快照的标签；换号、失败或连接变化时，标签、身份键与统计一起更新/裁剪。原工具来源优先当前账号，不使用旧邮箱快照冒充实时身份。
- 主内容宽度至少 1040px 时一行四卡，780px 三卡、560px 两卡，再窄一列；卡片内长账号可换行。非手动签到版本已有账号也可查看额度、删除，不新增手动领取能力。
- 删除有明确确认，执行中冻结关闭和重复操作；失败保留账号，成功仅删除指定连接和保存凭据，签到记录保留，其他账号不受影响。跨页在领奖 POST 已发送后删除连接，持久化仍保留原身份已发生领取记录，页面失效身份结果裁剪为待核实，避免历史丢失。

## 数据查询结果与范围

WorkBuddy 国内：真实只读状态确认有 `checkin_dates`（严格日期字符串数组）、`total_credits` 和服务端 HTTP Date。现按官方返回日期统计周/月/本期天数，去重并排除未来日期，接入原始本期累计奖励。日期数组没有明确全历史覆盖承诺，没有逐日奖励，界面持续说明范围；周/月奖励不能以当前日奖励乘天数估算。缺失/非法日期或服务端时间时相关天数未知，本机回退项单独标来源。详见 `2026-10-27-workbuddy-checkin-protocol.md`。

Trae 国内：真实只读当前数据为总积分 4700、已用 0，官方未直接返回剩余。现展示「可用额度（计算）4700」，并返回积分汇总与四个有数值的积分包；无已用的包保留未知，另一个无可识别额度的包不补零。不限量显式保留，不被原始范围优先规则吞掉。当前官方状态接口只提供今日签到，近期过期权益也不能作为完整签到历史。详见 `2026-10-27-trae-official-statistics.md`。

Qoder 双版：核对现有官方活动脚本只读 `/sash/api/v1/me/campaigns` 的当前轮次合约，保持逐范围额度与真实当前领取状态；周/月和累计仍明确为 Jolu 已记录历史，不能把当前活动状态冒充全历史。公开[每日活动说明](https://docs.qoder.cn/events/100credits)用于核对每日活动资格与时间，不是历史记录接口依据。

上述真实验证均只读，没有再次领奖、切号、写入原工具登录或删除真实用户账号。合成 UI 的多账号删除、保存与领取不等于多个真实账号领奖验收。
