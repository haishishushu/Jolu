# 签到顶部操作与刷新弹窗验收

## 需求与改动总结

鼠鼠要求「刷新状态」使用弹窗，并在其后放置「添加账号」按钮，先选择供应商，不使用账号卡片上的加号。

- 顶部依次显示隐藏账号、刷新状态、添加账号、一键签到；六张卡片均无加号。
- 添加账号先打开供应商与版本选择，再进入现有共用连接表单。列出六个版本，WorkBuddy AI 自动奖励与 Trae 国际尚无手动签到，显示说明且禁用选择。去连接、更新登录仍预选版本原地打开表单。
- 手动刷新弹窗显示读取进度、逐账号结果、错误与汇总；关闭后只读查询继续并更新卡片。首屏、返回前台和定时查询不会自动弹窗。查询不发送领取请求。
- 弹窗沿用现有 Radix、`useDialogClose` 和 `jolu-*` 主题；供应商列表与状态结果支持内容区滚动，账号隐私开关也用于弹窗。
- Pencil 133–140 同步顶部入口并删除卡片加号，新增 141–142 供应商选择与 143–144 刷新状态的浅深色画板；通过 MCP 截图与真实 React 运行截图对照。

交互脚本使用独立无头 Edge、真实 React 组件、合成 IPC，不触碰真实账号或领取。原签到回归因刷新弹窗和页面同时显示错误而出现定位歧义，已按新交互先核对弹窗错误、关闭弹窗，再验证页面重试。截图在 `output/acceptance/account-connect-dialogs/`。

实际桌面新交互操作受到持续的 user-input guard / 窗口最小化限制，没有绕过保护；本阶段确认的是上述组件交互、构建与设计对照，不将其表述为新弹窗的真实桌面 IPC 验收。正常 `jolu.exe` 进程仍响应。
